# Skill Validator Dependency Fix

## Summary

Closed the recurring skill quick-validator dependency gap by making `skills/.system/skill-creator/scripts/quick_validate.py` runnable when PyYAML is unavailable.

## Repository Changes

- Updated `skills/.system/skill-creator/scripts/quick_validate.py` so it still uses `yaml.safe_load` when PyYAML exists, but falls back to a conservative repo-local parser when `import yaml` fails.
- The fallback supports local skill frontmatter shapes: top-level scalar mappings and one-level nested scalar mappings such as `metadata`.
- The fallback rejects sequences, block scalars, flow-style collections, multiline values, and deeper nested mappings without PyYAML.

## Memory Updates

- Added this diary as the commit-message-ready run record.
- No separate lesson was added; the durable reusable change is the validator script itself, and the outbox records the proof.

## Skill Updates

- Changed only the bundled `skill-creator` quick validator script.
- Did not modify `skills/skill-first-branch-delivery/SKILL.md` and did not add trigger-review suppression.

## Decisions

- Preferred the smallest durable mechanism over another trigger-review ignore rule.
- Kept full YAML parsing delegated to PyYAML when available.
- Used `.self-harness/tmp/skill-validator-fixtures/` for positive and negative fixtures and `.self-harness/tmp/pycache` for Python bytecode cache during syntax checking.

## Risks Or Incidents

- The fallback is intentionally not a full YAML parser. Complex frontmatter still requires PyYAML; without PyYAML, unsupported shapes fail closed.
- An initial `python3 -m py_compile` attempt tried to write bytecode into an external Python cache and failed with a permission error. Rerunning with `PYTHONPYCACHEPREFIX=.self-harness/tmp/pycache` kept generated bytecode inside ignored repository scratch and passed.
