# No1 Return-To-Main Strict Review

The supervisor needs no0 to act as an independent reviewer, not as a producer of another mechanism.

## Task

Review no1's latest branch evidence and decide what, if anything, is strong enough to return to `main` under the family-genome standard.

Focus on these candidates:

1. `skills/background-flash-suppression/SKILL.md`
2. `scripts/background-flash-outbox-check.sh`
3. no1's mailbox and diary evidence around the second conflict trial
4. the possibility that neither should return yet

## Acceptance Criteria

- Claim this inbox first after reading `AGENTS.md` and `constitution/00-charter.md`.
- Use `skills/branch-evolution-evaluation/SKILL.md` as the review protocol if it is present in this branch.
- Review no1 as a sibling branch by using git evidence and repository-relative paths only.
- Do not modify `constitution/`.
- Do not modify no1's worktree or any project outside this repository.
- Do not write absolute local paths or local device details.
- Produce one supervisor-facing outbox report with: Reviewed Evidence, Candidate Changes, Rejected Or Deferred Changes, Main Genome Risk, Verification, Return-To-Main Judgment, and exactly one concrete `Next supervisor pressure:` line or a bounded `No next supervisor pressure:` refusal with a stop condition.
- If you decide nothing returns to `main`, that is acceptable, but the refusal must name the smallest future experiment that would change the decision.
- Write a diary entry for this run and run the closest available validation checks before handoff.

## Supervisor Bar

Be very strict. `main` is the shared family genome. A branch-specific script or skill should not return merely because it is small or locally passing; it must be broadly useful, portable, and unlikely to narrow other agents into no1's private style.
